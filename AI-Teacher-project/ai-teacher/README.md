# 🎓 AI Teacher — Human-Like AI Educator That Teaches Through Video

Built for **AI Innovation Hackathon 2026** (Bharat Academix) — Challenge: *AI Teacher: Build a Human-Like AI Educator That Teaches Through Video*.

Not a chatbot. A system that **plans a lesson, teaches it through a narrated video with a subject-aware diagram and a talking avatar, checks understanding along the way, detects misconceptions and re-teaches, then assesses and reports** — the way a real tutor would run a 1-on-1 session.

## Why this submission is different

Most hackathon entries in this track will either (a) wrap a chatbot in a video player, or (b) require the judge to supply three paid API keys before anything runs. This project deliberately avoids both traps:

- **Runs with zero API keys.** An offline, deterministic "mock" LLM provider (`backend/llm/mock_provider.py`) drives the *entire* pipeline — lesson planning, adaptive Q&A, quiz generation, scoring — so a judge can `pip install -r requirements.txt && python backend/app.py` and see a real generated video and a real adaptive-teaching loop in under two minutes, no signup required.
- **Upgrades instantly.** Set `ANTHROPIC_API_KEY` or `OPENAI_API_KEY` and every lesson, explanation, and evaluation is immediately generated by a real frontier model — no code changes, because every teaching module talks to an abstract `LLMProvider` interface, not a specific vendor SDK.
- **Actually produces a video file**, end to end, with ffmpeg only: a subject-aware diagram (different rendering per subject — equations for math, timelines for history, labeled diagrams for biology, syntax-highlighted code for programming), a simple talking 2D avatar, burned-in captions, and real spoken narration — `pip install -r requirements.txt` alone pulls in `pyttsx3` (fully offline, no key) so the video has actual sound, with `gTTS`/ElevenLabs/Azure as drop-in upgrades. (On Linux, `pyttsx3` also needs the system package `espeak-ng`: `sudo apt install espeak-ng`.)
- **Grounded, not hallucinated.** Uploaded material is chunked and indexed (`backend/ingestion/retriever.py`) and every lesson section built from a document is retrieved from that index, not invented. Two retrieval backends ship behind one interface: TF-IDF by default (zero setup), or set `EMBEDDING_BACKEND=dense` for sentence-transformers embeddings in a **FAISS vector database** — a genuine vector-DB implementation, not just a keyword match.
- **Answer by voice, not just text.** Every checkpoint question has a 🎤 button alongside the textbox — `media/stt.py` transcribes the recording with **faster-whisper** (fully offline, no key) and scores it exactly like a typed answer, so the lesson feels like talking with a tutor instead of filling out a form.
- **Sees images, not just text.** `backend/ingestion/vision.py` extracts embedded pictures from DOCX/PPTX and renders/OCRs image-only ("scanned") PDF pages with **Tesseract**, so a diagram with labels, a formula that's actually a picture, or a scanned textbook page gets folded into the same RAG index instead of silently disappearing.

See `docs/EVALUATION_MAPPING.md` for a point-by-point mapping of this codebase to the assessment's 20 numbered requirements and its evaluation rubric.

## Quick start

```bash
cd backend
pip install -r requirements.txt
python app.py
# open http://localhost:5000
```

That's it — no `.env` file is required to see the full pipeline work. To upgrade quality, copy `.env.example` to `.env` and fill in whichever keys you have (see below).

## What you can do in the UI

1. **Upload** a PDF / DOCX / PPTX / TXT, or just type a topic.
2. Choose **level** (beginner/intermediate/advanced), **time available** (5 / 20 / 60 min), and **teaching language**.
3. Click **Generate Lesson Plan** — a structured, personalized plan appears (objectives, sections, examples, a subject-appropriate visual per section, a checkpoint question per section).
4. Click **Generate Teaching Video** — a real `.mp4` is rendered and playable in-browser: narrated, captioned, with a talking avatar and a diagram matched to the subject of each section.
5. Answer each section's **checkpoint question** inline — the system evaluates it, and if you're wrong or partially right, it detects *why* and re-explains with a **different analogy**, not a repeat of the same text.
6. Click **Generate End-of-Lesson Quiz**, answer it, and get a **learning report**: score, strong/weak concepts, a specific recommendation, and a suggested next topic.
7. Your **learning profile** (topics studied, weak/strong concepts, recommended next step) persists in SQLite and is shown at the bottom — future sessions for the same student ID are personalized against this history.

## Architecture

```

  app.py                     Flask API + serves the frontend
  llm/                       Model-agnostic LLM abstraction
    base.py                    LLMProvider interface + provider factory
    mock_provider.py           Offline, zero-dependency demo provider
    anthropic_provider.py      Claude backend
    openai_provider.py         GPT backend
    ollama_provider.py         Local/offline real-LLM backend
  ingestion/                 Learning-material processing (RAG)
    extract.py                  PDF / DOCX / PPTX / TXT -> plain text
    chunker.py                  Paragraph-aware overlapping chunking
    retriever.py                TF-IDF or FAISS+sentence-transformers index (EMBEDDING_BACKEND)
  teaching/                  The pedagogy layer
    lesson_planner.py           Topic/material + learner profile -> lesson plan
    adaptive_engine.py          Answer evaluation, misconception detection, re-teaching
    assessment.py                Quiz generation, grading, learning report
    profile_store.py             SQLite: persistent per-student learning history
  media/                     The "video-based AI Teacher" layer
    slides.py                    Subject-aware slide/diagram rendering (PIL + matplotlib)
    avatar.py                    2D talking-avatar frame generation
    tts.py                       Pluggable narration (ElevenLabs/Azure/gTTS/pyttsx3/silent)
    video_builder.py             Assembles narrated, captioned .mp4 via ffmpeg
  static/                    Vanilla HTML/CSS/JS frontend (no build step)
docs/
  ARCHITECTURE.md              Deeper design notes + production upgrade path
  EVALUATION_MAPPING.md        Requirement-by-requirement coverage table
sample_output/
  demo_lesson.mp4               A real video generated by this pipeline
```

See `docs/ARCHITECTURE.md` for the request/response flow diagram and the exact points where you'd plug in a production-grade avatar/voice service.

## Configuration (`.env`)

Copy `.env.example` to `.env`. Every variable is optional — the system runs fully offline without any of them.

| Variable | Effect |
|---|---|
| `ANTHROPIC_API_KEY` | Use Claude for all lesson planning / teaching / grading |
| `OPENAI_API_KEY` | Use GPT for the same (used only if no Anthropic key) |
| `OLLAMA_MODEL`, `OLLAMA_HOST` | Use a local, free, offline LLM instead |
| `ELEVENLABS_API_KEY`, `ELEVENLABS_VOICE_ID` | High-quality multilingual narration |
| `AZURE_SPEECH_KEY`, `AZURE_SPEECH_REGION`, `AZURE_VOICE_NAME` | Azure Neural TTS narration |
| (none of the above) | Falls back to gTTS if internet is available, then pyttsx3 if installed, then a correctly-timed silent track |

## Known limitations (disclosed per submission requirements)

- **Avatar realism**: the avatar is a simple, original 2D vector illustration with a two-state mouth toggle approximating lip-sync — not a photoreal talking head. `docs/ARCHITECTURE.md` shows exactly where to swap in D-ID / HeyGen / Synthesia / a self-hosted SadTalker or Wav2Lip model behind the same `render_avatar()` call.
- **Offline mock provider quality**: without an LLM API key, lesson text is produced by extractive/templated heuristics, not true generation. It is designed to prove the pipeline and RAG grounding work, not to replace a real LLM for the final graded demo — set `ANTHROPIC_API_KEY` or `OPENAI_API_KEY` for full quality.
- **RAG retrieval default**: `EMBEDDING_BACKEND=tfidf` is the out-of-the-box default because it needs no model download, so recall on heavily paraphrased queries is weaker than the dense option. Set `EMBEDDING_BACKEND=dense` for the sentence-transformers + FAISS vector-database backend (see `docs/ARCHITECTURE.md`) for better semantic recall once `sentence-transformers`/`faiss-cpu` are installed.
- **Answer grading for short-answer questions** currently goes through the same LLM abstraction used everywhere else (correct, by design) but has not been evaluated against a large rubric-graded dataset — treat scoring as indicative, not exam-grade.
- **Single-process, in-memory lesson/quiz store**: fine for a demo/single grader session; a production deployment should move `_LESSONS`/`_QUIZZES` in `app.py` into the same SQLite (or Redis) store used for profiles.
- **No authentication**: `student_id` is a free-text field for demo purposes.

## Deployment

Any host that can run Python + ffmpeg works (Render, Railway, a VM, etc.):

```bash
pip install -r backend/requirements.txt
export ANTHROPIC_API_KEY=...        # optional but recommended for the real demo
export ELEVENLABS_API_KEY=...       # optional, for higher-quality narration (pyttsx3 already gives real speech with no key)
cd backend && gunicorn -w 2 -b 0.0.0.0:$PORT app:app
```

`gunicorn` isn't in requirements.txt by default (keeps the zero-dependency demo path minimal) — add `gunicorn` for production; `python app.py` is fine for local judging.
